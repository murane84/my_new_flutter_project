# Aluta — Third-Party / Open-Source Licenses (Producer Record)

**Internal reference — NOT shipped in the app UI.**
Keep this file with your source. It records the open-source packages Aluta
depends on and their licenses, so you can produce attribution on request (e.g.
if a store, auditor, or licensor asks) without exposing a licenses page to end
users. The in-app "Open-source licenses" screen has been removed.

Last compiled: 4 August 2026 — for Aluta v1.0.0+1.

---

## How to regenerate the *authoritative* full-text list

The list below is a best-effort summary compiled from `pubspec.yaml`. The
complete, always-accurate license **full text** for every bundled package
(including transitive dependencies and the Flutter/Dart engine's own third-party
components) is generated by Flutter itself. To export it whenever you need it:

**Option A — view it in a throwaway build.** Temporarily re-add this tile to
`showLegalMenu` in `legal_screen.dart`, run the app, open the page, then remove
the tile again:

```dart
showLicensePage(
  context: context,
  applicationName: 'Aluta',
  applicationLegalese: '© 2026 Aluta',
);
```

**Option B — generate a file with a dev tool.** Add `flutter_oss_licenses` as a
`dev_dependency`, then run its generator; it writes a Dart/JSON file listing
every dependency and its license text. This is the cleanest way to keep an
exportable record without any user-facing screen.

Either option reflects the exact dependency set at build time, which is the
version you should hand over if attribution is ever requested.

## Notes

- **This is a summary, not the license texts.** MIT, BSD-2-Clause, and
  BSD-3-Clause all require that the copyright notice and permission notice be
  preserved in distributions. If you ever publish attribution, use the full-text
  export (Option A or B above), which includes each package's copyright line.
- **Transitive dependencies** (packages pulled in by the ones above) are not
  listed here individually but *are* included in the Flutter-generated export.
- Licenses can change between versions. This record is pinned to the versions in
  `pubspec.yaml` / `pubspec.lock` at the date above; re-compile it if you bump
  dependencies.
